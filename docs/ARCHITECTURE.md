# Shumo：Workflow 主导、Agent 受控的三层架构

## 1. 架构目标

Shumo 同时解决两个结构问题：

1. 把“解题研究”和“论文成稿”拆开，避免计算约束、探索记录和重复公式直接进入正文；
2. 把“确定性流程”和“开放自主探索”拆开，避免所有任务都被包装成高成本、难调试的 Agent。

总原则是：

> 能画出决策树的任务使用 Workflow；只有高价值、真正模糊、关键能力可靠且错误可发现的任务，才使用受控 Agent。

## 2. 总体流程

```text
W0 项目初始化
        │
W1 题目解析与交付清单
        │
G1 Agent 准入闸门
   ┌────┴──────────────┐
   │不需要             │需要
   │                    ▼
   │              A1 路线探索 Agent
   │                    │
   └──────────────► H1 参赛者路线确认
                         │
W2 模型规格化 ◄─────────┘
        │
W3 代码实现与数值求解
        │
W4 结果验证
        │
G2 评审 Agent 准入闸门
   ┌────┴──────────────┐
   │跳过                │通过
   │                    ▼
   │              A2 方案压力测试
   │                    │
   └──────────────► W5 成果包与登记库固化
                         │
             第一层输出 problemX.model.yaml
                         │
W6 第二层：论文架构与全局登记
                         │
             输出 paper_blueprint.yaml
                         │
W7 第三层：论文写作与成稿
                         │
W8 重复、编号、数值和附件一致性检查
```

`W` 表示确定性 Workflow，`G` 表示准入判断，`A` 表示可选受控 Agent，`H` 表示人工决策点。

## 3. 三层职责

### 3.1 第一层：建模与求解

负责：

- 题目解析；
- 候选路线和创新探索；
- 模型规格与公式推导；
- 算法、代码和数值结果；
- 验证和风险；
- 建模成果包。

第一层不是单体 Agent。题目解析、规格化、实现和验证均使用 Workflow；只有路线探索、未知故障诊断和方案评审可申请 Agent。

### 3.2 第二层：论文架构与全局登记

负责：

- 整篇章节结构；
- 模型和公式唯一所有者；
- 公共符号和假设；
- 最终编号；
- 前问继承与后问新增；
- 页数和详略；
- 登记库更新。

第二层是确定性控制流，不重新建模，也不允许 Agent 自由调整数学事实。

### 3.3 第三层：论文写作与成稿

负责将成果包和蓝图写成 LaTeX、Word 或 Markdown。

第三层不得：

- 重新建模；
- 重新求解；
- 重新编号；
- 调用探索 Agent；
- 临时增加创新点；
- 猜测缺失结果。

## 4. Agent 准入闸门

每次启用 Agent 前必须回答四个问题：

1. **问题空间是否模糊**：若完整决策树可枚举，使用 Workflow；
2. **任务价值是否足够**：回报必须覆盖成本、延迟和错误风险；
3. **关键能力是否可靠**：例如建模、调试或评审能力已有证据；
4. **错误是否可发现**：必须有测试、残差、对照、检查点和回滚。

决策只允许：

```text
workflow
bounded_agent
human_checkpoint
blocked
```

Agent 自主程度不得高于系统发现其错误的能力。

## 5. 允许的 Agent 插槽

### 5.1 Route Explorer

用于：

- 比较多条候选建模路线；
- 发现题目特有结构；
- 构造可验证改进。

它只生成候选，最终路线由参赛者确认。

### 5.2 Diagnostic Agent

用于无法由预定义故障树解释的代码或数值问题。

调用条件：

- 已有最小复现；
- 已有测试和日志；
- 已有回滚点；
- 修复范围明确。

它不得同时修改模型、登记库和论文。

### 5.3 Solution Review Agent

用于关键方案的压力测试：

- 隐藏假设；
- 反例和边界；
- 不可辨识和多解；
- 脆弱阈值；
- 简化机会；
- 验证缺口。

它只给评审证据和建议，不直接批准或修改最终成果。

## 6. Environment、Tools、Prompt

Agent 只围绕三个基础组件设计。

### 6.1 Environment

必须显式声明：

- 可读路径；
- 可写路径；
- 不可变路径；
- 当前问题；
- 已加载成果；
- 明确未知信息；
- 回滚点。

Agent 不得假设自己知道未加载的文件或设计者脑中的隐含状态。

### 6.2 Tools

工具接口必须说明：

- 必需输入；
- 返回观察；
- 副作用；
- 失败信号；
- 重试上限；
- 调用后验证。

工具返回空值、部分成功或错误时，不能被当成成功。

### 6.3 Prompt

Prompt 必须同时定义：

- 目标；
- 成功标准；
- 已知和未知；
- 允许与禁止动作；
- 必需检查；
- 输出 schema；
- 预算；
- 停止和升级条件。

## 7. Agent 视角模拟

设计者应从 Agent 的受限视角完整执行一次任务：

1. 它现在能看到什么？
2. 下一步需要的信息是否明确提供？
3. 工具调用后会返回什么？
4. 它如何判断动作真的成功？
5. 空结果、单位错误和部分成功能否识别？
6. 哪个约束只存在于设计者脑中？
7. 哪个行动可能造成静默错误？

发现认知缺口时，优先改 Prompt、工具和 Workflow，而不是增加 Agent 复杂度。

## 8. 最小执行循环

```text
Observe
→ 明确当前缺口
→ 选择一个有边界动作
→ 调用一个工具或生成一个候选
→ 对比预期证据与实际证据
→ 更新状态
→ 继续、停止、回滚或升级
```

每轮不得同时改变模型、代码、结果和论文结构。

## 9. 数据合同

### 9.1 第一层 → 第二层

`problemX.model.yaml` 是研究事实源，包括：

- 模型依赖；
- 路线决策记录；
- Agent 准入和运行记录；
- 新旧符号；
- 公式语义 ID；
- 算法；
- 结果；
- 验证；
- 评审发现；
- 创新路线；
- 论文必须体现和应省略内容。

第二层不得越过成果包自行补模型。

### 9.2 第二层 → 第三层

`paper_blueprint.yaml` 是写作控制源，包括：

- 章节核心结论；
- 模型和公式所有者；
- 最终标签和编号；
- 前文引用；
- 新增内容；
- 图表和结果落点；
- 约束的正文、算法、附录和省略分类；
- 页数预算。

第三层不得绕过蓝图自由扩写。

## 11. 公式生命周期

1. 第一层用语义 ID 建立公式；
2. 第二层指定首次定义章节和 LaTeX 标签；
3. 第三层只在所有者章节完整写出；
4. 后续章节使用式号引用；
5. 审查脚本根据项目合同检查禁止重复内容。

## 12. Token 与上下文控制

每次执行只加载：

- 当前 Workflow 或 Agent 的规则；
- 项目配置；
- 当前问题输入；
- 项目登记库；
- 直接依赖成果；
- Agent 显式环境清单。

默认禁止为处理单个问题而通读整个仓库或所有历史正文。

## 13. 复杂性升级顺序

```text
改进 Prompt
→ 改进工具输入输出
→ 增加确定性检查
→ 增加单次候选生成
→ 最后才增加多轮 Agent
```

行为未稳定前，不引入多 Agent 讨论、长期记忆、自主递归规划或无限反思循环。

## 14. 设计原则

- Workflow 是骨架，Agent 是有限插槽；
- 研究事实、论文结构和论文表达分别管理；
- 先设计错误检测，再授予行动权限；
- 参赛者保留高价值路线取舍权；
- 创新来自题目结构、基线缺陷和验证，不来自复杂包装；
- 论文体现必要约束，但不复制全部调试保护条件；
- 任何未验证 Agent 结论不得进入最终正文。
