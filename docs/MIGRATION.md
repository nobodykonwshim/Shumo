# 从旧版单体 Skill 迁移到三层架构

## 1. 迁移原则

本次重构不删除现有 `2024A/` 项目库、公式登记库、参数库、模型合同或审查脚本。旧版内容继续保留，通用入口改为路由器，并新增三层职责文件。

迁移重点不是重写已有数学成果，而是改变后续任务的调用顺序和产物格式。

## 2. 旧版问题

旧版 `skills/math_modeling/SKILL.md` 同时包含：

- 题目分析与建模；
- 公式推导与数值求解；
- 论文结构与正式语言；
- Word、LaTeX、图表和交付规则。

这会造成：

1. 建模阶段被论文格式约束过早干扰；
2. 计算约束和调试细节被写入论文；
3. 每一问为了“完整”重复前一问公式；
4. 单题独立生成时公式编号重新开始；
5. 创新点在写作阶段临时包装，而非在建模阶段验证；
6. 每次任务需要加载过多上下文。

## 3. 新版调用方式

### 3.1 新项目

1. 复制 `skills/math_modeling/config/project_config.example.yaml` 到 `<project>/project.yaml`；
2. 创建 `<project>/registry/`；
3. 对每一问先调用第一层，生成 `problemX.model.yaml`；
4. 完成若干问题后调用第二层，生成或更新 `paper_blueprint.yaml`；
5. 调用第三层写当前章节；
6. 运行公式复用和结果一致性检查。

### 3.2 现有项目

以 `2024A/` 为例：

- 继续使用现有 `registry/parameters.yaml`；
- 继续使用现有 `registry/formulas.yaml`；
- 继续使用现有 `registry/model_contracts.yaml`；
- 为后续问题补充 `artifacts/modeling/problemX.model.yaml`；
- 为整篇论文建立 `artifacts/architecture/paper_blueprint.yaml`；
- 现有 `sections/*.tex` 不强制重写，后续修改按第三层规则执行。

## 4. 旧指令到新指令的映射

| 旧请求 | 新执行方式 |
|---|---|
| “使用数模 Skill 分析问题四” | 入口路由到第一层 |
| “给出问题四建模思路，确认后再写” | 第一层先输出候选路线与成果包草案 |
| “整理完整问题四模型建立与求解” | 第一层完成成果包，第二层规划本节，第三层成稿 |
| “问题五不要重复问题四公式” | 第二层将问题四设为公式所有者，问题五只引用 |
| “给出创新点” | 第一层调用 Innovation Explorer，不能直接在第三层包装 |
| “生成 Word 版” | 第三层读取蓝图与成果包后生成 |
| “审核论文公式是否重复” | 第二层审查所有权，随后运行复用检查脚本 |

## 5. 兼容规则

- `FORMULA_REUSE_PROTOCOL.md` 继续有效；
- `check_formula_reuse.py` 的参数与调用方式保持不变；
- 项目专用公式和参数不得移入 `skills/`；
- 旧版单题 `.tex` 可以继续编译；
- 新版语义公式 ID 可逐步补充，不要求一次性改完旧项目；
- 没有成果包的旧章节可先通过“反向提取”生成成果包，再进入新流程。

## 6. 推荐的反向提取流程

对已有章节：

1. 读取章节和结果附件；
2. 提取模型组件、公式、算法、结果和验证；
3. 标记每个公式的首次定义位置；
4. 生成对应 `problemX.model.yaml`；
5. 更新项目公式登记库；
6. 在论文蓝图中标记后续问题的引用关系；
7. 不改变已验证数值，除非第一层复核发现错误。

## 7. 完成标准

项目完成迁移后，应能够回答：

- 当前任务属于哪一层；
- 当前问题依赖哪些前序模型；
- 每个基础公式在哪一节首次定义；
- 当前章节允许新增什么、禁止重复什么；
- 结果来自哪个成果包或附件；
- 创新点对应哪个基线缺陷和验证结果；
- 处理当前任务需要加载哪些最小文件集合。
