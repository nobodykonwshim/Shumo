# 数学建模竞赛 Skill 执行补充规则

本文件补充 `skills/math_modeling_competition_skill.md`。

## 1. 读取 skill 后必须按清单执行

当用户要求“严格按照数模 skill 进行”时，不能只读取 skill 后直接计算结果。必须把 skill 转化为执行清单，并按以下顺序组织任务：

```text
题目条件 → 问题分析 → 模型假设 → 符号定义 → 简图说明 → 公式推导 → 算法求解 → 数值结果 → 可靠性检验 → 模型评价
```

输出前必须检查每一项是否已经体现。若某项确实不适用，应说明原因；不能隐式跳过。

## 2. 禁止把完整数模任务简化为结果计算任务

若题目要求输出 Excel、代码、图像或数值结果，仍不能只完成计算和文件生成。正确顺序是：

```text
先建立论文结构 → 再建立模型 → 再配置示意图 → 再推导公式 → 再设计算法 → 再计算结果 → 再验证与评价
```

禁止顺序：

```text
先算结果 → 直接写结论 → 简略补文字
```

## 3. 简化示意图为几何与运动问题的强制项

凡涉及几何关系、空间位置、轨迹运动、路径规划、速度方向、碰撞检测、刚体连接、边界约束或坐标变换，必须先配置简化示意图，再写公式。

简图用于说明变量位置、方向、距离、边界和约束来源。图后必须回到数学公式，不能只靠图解释。

## 4. 所有简图必须可人工修改

简化示意图必须使用以下方式之一绘制：

1. HTML + SVG 或 HTML + Canvas；优先 SVG，因为点、线、箭头、文字和区域便于人工修改。
2. MATLAB 绘图代码；使用 `plot`、`patch`、`rectangle`、`quiver`、`text` 等函数，并保留完整代码。

不得只提供不可编辑截图、位图或静态图片。若给出图片预览，也必须同时提供 HTML/SVG 源码或 MATLAB 绘图代码。

## 5. 正式论文表达约束

数模 skill 的作用是帮助生成标准数学建模论文，而不是把执行约束、写作规则或思考过程写进论文正文。正式文档中不得出现类似下列元说明：

- “按照数模求解流程，应先配置简化示意图，再进行公式推导。”
- “为保证示意图可人工修改，本文同时提供 HTML/SVG 源文件与 MATLAB 绘图代码。”
- “根据 skill 要求，本节进行结构完整性检查。”
- “下面按照问题分析、模型假设、符号说明的流程展开。”

正式论文正文只能呈现研究对象、模型假设、变量定义、公式推导、算法说明、结果分析和模型评价。内部执行规则只用于保证输出质量，不应显性出现在正文中。

## 6. Word 与正式文档字体规范

生成 Word、论文正文、建模报告等正式文档时，默认采用以下字体规范：

1. 中文统一使用宋体。
2. 英文和数字统一使用 Times New Roman。
3. 表格、图题、表题、公式编号、脚注和正文中的变量说明均遵循上述中英文字体区分。
4. 若用户另行指定学校、竞赛或模板格式，则以用户指定模板为准，但仍优先保持中文宋体、英文和数字 Times New Roman 的基本规范。

## 7. 输出前结构检查

最终输出前必须检查：问题分析、模型假设、符号说明、简图、公式推导、求解算法、初值与搜索区间、约束与停止条件、结果表、残差或合理性检验、模型评价是否完整。

该检查属于内部质量控制，不应以“检查清单”或“按照 skill”之类表述写入正式论文正文，除非用户明确要求展示检查过程。
