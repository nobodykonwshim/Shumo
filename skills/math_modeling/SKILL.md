# 数学建模写作与求解 Skill

## 适用范围

本 Skill 用于数学建模竞赛、数模论文撰写、模型审核、模型重写、结果解释、结果表格整理和答辩材料整理等任务。凡用户要求“使用数模 skill”“建模与求解”“论文版”“审核模型”“整理完整模型”时，均优先按本规范组织输出。

## 总体写作结构：总—分—总

每一个问题的解决必须采用“总—分—总”的结构，而不是直接堆公式或直接给结果。

### 1. 开头之“总”：问题解决思路总述

每一问开头先用一段完整文字说明：

- 本问要解决的核心目标是什么；
- 已知条件、约束条件和需要输出的结果是什么；
- 采用什么总体建模思路；
- 求解流程分为哪几步；
- 每一步之间的逻辑关系是什么。

开头总述应让读者在进入公式前已经知道“为什么这样建模、接下来要推导什么、最终如何得到结果”。

推荐句式：

> 本问的核心目标是……。为此，本文首先……，然后……，接着……，最后……。通过上述流程，可以将题目要求转化为……，并进一步得到……。

### 2. 中间之“分”：逐步模型推导

中间部分必须按步骤展开数学模型，不得遗漏关键推导，不得从结论跳到结果。

每一步至少包括：

1. 该步骤的建模目的；
2. 变量和参数定义；
3. 数学公式或约束关系；
4. 公式来源或推导过程；
5. 求解方法或数值实现方式；
6. 与下一步之间的衔接说明。

公式推导要求：

- 公式中出现的新变量必须及时解释；
- 单位必须统一，题目中 cm 应转为 m 后再参与计算；
- 关键约束不得只用文字描述，必须写成数学表达式；
- 涉及递推、优化、碰撞检测、速度约束、边界条件时，应明确索引范围；
- 涉及数值求解时，应说明搜索区间、精度、停止准则和误差检验方式；
- 不使用“显然可得”“容易得到”替代关键推导，除非该步确实非常基础。

推荐层级：

```text
X.1 本问求解思路
X.2 模型建立
    X.2.1 ……模型
    X.2.2 ……约束
    X.2.3 ……递推/优化/判定方法
X.3 模型求解
X.4 结果与分析
```

### 3. 结尾之“总”：计算结果、解释与结论

每一问结尾必须集中给出结果和解读，而不是只放表格。

结尾部分应包括：

- 关键计算结果；
- 结果表格或图的文字解释；
- 结果是否满足题目约束；
- 必要的误差检验或稳定性检验；
- 本问结论性回答。

推荐句式：

> 综上，本问通过……模型和……方法得到……。计算结果表明……，说明……。结合误差检验可知……，因此本文认为……。

## 求解思路流程图要求：Draw.io

每一个数学建模问题都必须绘制“求解思路流程图”，并将流程图插入该问正文中。流程图作为“总—分—总”结构中开头总述与中间模型推导之间的桥梁，用于直观展示本问从已知条件到模型建立、数值求解、结果输出和误差检验的完整逻辑链条。

### 1. 插入位置

流程图应放置在每一问的“本问求解思路”之后、“模型建立”之前。推荐正文结构为：

```text
X.1 本问求解思路
    用一段话总述目标、思路和流程。
    插入：图 X 问题X求解流程图
X.2 模型建立与推导
X.3 模型求解
X.4 结果与分析
```

图前必须说明绘图目的，例如：

> 为清晰展示本问从已知条件到结果输出的建模逻辑，本文绘制问题 X 的求解流程图，如图 X 所示。

图后必须解释流程图含义，例如：

> 由图 X 可知，本问的求解过程可分为……、……和……三个阶段，各阶段依次衔接，最终得到……。

### 2. 绘制工具与文件要求

流程图应使用 draw.io（diagrams.net）绘制，并至少保留两类文件：

- `*.drawio`：源文件，便于后续修改；
- `*.png` 或 `*.svg`：导出文件，用于插入 Word、PDF 或 LaTeX 论文。

推荐命名方式：

```text
p1_flow.drawio
p1_flow.png
p2_flow.drawio
p2_flow.png
p3_flow.drawio
p3_flow.png
```

当用户要求“Word版”“论文版”“完整建模与求解”时，应在最终文档中插入对应流程图；若当前环境无法直接生成 draw.io 源文件，应至少给出可直接转换为 draw.io 的流程图结构，并在可生成图片时同步插入图片。

### 3. 流程图内容要求

流程图必须与正文建模步骤一一对应，不能只画空泛流程。通常应包含以下节点：

1. 题目输入与已知条件；
2. 参数换算与符号定义；
3. 核心模型建立；
4. 约束条件构建；
5. 递推、优化、搜索或判定算法；
6. 数值求解与结果输出；
7. 误差检验或稳定性检验；
8. 结论解释。

不同问题应突出不同重点：

- 轨迹或运动问题：突出“轨迹方程 → 位置递推 → 速度递推 → 结果输出”；
- 碰撞或终止问题：突出“候选筛选 → 精确判定 → 终止时刻搜索 → 位置速度输出”；
- 优化问题：突出“决策变量 → 目标函数 → 约束条件 → 搜索/优化 → 最优性验证”；
- 路径设计问题：突出“几何约束 → 相切条件 → 曲线参数求解 → 路径长度/可行性分析”；
- 最大速度问题：突出“单位速度场 → 速度比例系数 → 最坏把手识别 → 最大龙头速度”。

### 4. 图题与图文规范

流程图图题统一写为：

```text
图 X  问题X求解流程图
```

其中 X 与论文中的问题编号一致。

流程图应保持清晰、简洁、黑白打印友好。节点文字应使用论文中的关键词，不使用过长句子；流程方向应从上到下或从左到右，避免交叉线过多。颜色可使用蓝色系作为主色，红色用于关键判定或终止条件，但不能依赖颜色表达唯一含义。

## 数模论文表达规范

1. 先建模，后求解，再解释结果。
2. 结果不能孤立出现，必须说明其数学含义和题目含义。
3. 表格前要说明表格展示什么，表格后要解释表格说明什么。
4. 图前要说明为什么画图，图后要说明从图中得到什么结论。
5. 不写口语化表达，例如“我们发现”“可以看到一点点”等，应使用“结果表明”“由表可知”“进一步说明”等。
6. 不夸大模型效果，不声称没有验证过的结论。
7. 若结果来自程序，应补充数值误差、约束满足情况或稳定性说明。

## 数值求解与结果校验要求

只要涉及数值计算，就应尽量给出校验指标。例如：

- 约束误差：检验几何约束、距离约束、边界约束是否满足；
- 速度误差：检验速度大小、速度上限或速度递推是否满足；
- 目标函数值：检验优化问题求得的解是否合理；
- 稳定性检验：检验步长、精度、初值变化对结果的影响；
- 文件完整性：检验结果文件是否覆盖题目要求的全部时刻、全部对象和指定精度。

误差检验建议以小表格形式给出。

## 板凳龙类问题专用要求

处理“板凳龙”问题时，应特别注意：

1. 所有长度统一使用 m；
2. 龙头板长、龙身板长、孔中心距必须正确换算；
3. 把手编号必须与题目一致；
4. 位置结果与速度结果应严格对应题目指定时刻；
5. 若使用递推模型，应说明唯一解选取原则；
6. 若涉及碰撞，应说明粗筛和精判方法；
7. 若涉及调头路径，应说明切点、相切条件、半径约束和路径唯一性；
8. 若涉及最大速度，应说明速度比例关系或最坏时刻、最坏把手的判定方式。

## 输出风格

当用户要求“论文版”“完整建模与求解”“可以写入论文”时，输出应直接采用论文正文风格，不写操作建议式语言。

当用户要求“审核”时，输出应先给核心问题，再按模型完整性、推导严密性、求解可复现性、结果可信度、论文表达规范进行评价。

当用户要求“Word版”或“文档版”时，应生成可下载文档，并尽量保持公式可编辑、表格规范、图表标题完整；每一问均应插入对应 draw.io 求解流程图或其导出图片。
