# 第三层：论文写作与成稿

## 1. 职责

本层只解决“如何把已经确认的模型、算法和结果准确写成论文”。它是执行层，不拥有建模决策权和全局编号权。

本层负责：

- 按论文蓝图生成正式章节；
- 将结构化建模成果转化为连贯学术表达；
- 正确引用前文公式、图表和模型；
- 用必要文字体现题目约束和方法选择；
- 组织图—表—文关系与结果解释；
- 输出 LaTeX、Word、Markdown 或指定格式；
- 在成稿后执行重复定义、编号、语言和结果一致性检查。

本层禁止：

- 新增或更换模型；
- 补造第一层没有计算的结果；
- 重新推导已有公式；
- 自行修改符号含义、公式标签和编号；
- 为追求“完整”复制前一问的基础模型；
- 把第一层的内部约束、调试阈值和探索记录全部写进正文；
- 使用“按照 Skill”“根据用户要求”“代码生成”等元叙述。

若蓝图或成果包不足，输出缺口清单并退回对应层，不得猜测补全。

## 2. 强制输入

只读取：

1. 项目配置；
2. 已批准的 `paper_blueprint.yaml`；
3. 当前章节对应的建模成果包；
4. 当前章节引用的前序公式与结果条目；
5. 目标格式规范和题目原始交付要求。

不得默认加载其他问题的完整正文。引用前文时优先读取蓝图和公式登记库，以减少上下文和 token 消耗。

## 3. 写作规则

### 3.1 先承接，再新增

后续问题开头用简洁段落说明：

- 沿用了前文什么模型；
- 本问改变了什么条件；
- 本问新增了什么目标、变量、约束或判定；
- 本节最终要输出什么。

推荐结构：

```text
沿用前文模型及式号
→ 说明本问新增条件
→ 建立本问新增模型
→ 给出求解算法
→ 展示结果与验证
```

不得为了单节独立阅读而重新抄写前文轨迹方程、坐标表达、递推公式、实体几何模型或碰撞判据。

### 3.2 约束要体现，不要倾倒

第一层的约束在论文中按第二层分类处理：

- `must_show`：写出数学式并解释来源；
- `reference_only`：引用前文式号；
- `algorithm_only`：放在数值求解说明中，通常不编号；
- `appendix_only`：正文简述，细节放附录；
- `omit`：不进入最终论文。

因此，“论文中体现约束”是指读者能够理解模型为何成立和如何求解，不是把计算程序中的所有限制逐条复制到正文。

### 3.3 公式控制

- 只定义蓝图中 `formula_plan.define` 的公式；
- 对 `formula_plan.reference` 中的公式使用 `\eqref{}` 或文字引用；
- 不编号普通代数整理和临时中间式；
- 一个小节围绕少量核心公式展开；
- 新符号首次出现时解释，公共符号不重复建表；
- 公式推导保留关键数学动作，不省略决定模型成立性的积分、求导、投影、递推或极值步骤。

### 3.4 论文语言

正式正文应采用研究者陈述口吻：

- 使用“本文”“本节”“结果表明”“由式可知”等学术表达；
- 不使用“建议”“参考”“你可以”“我生成”等操作性语言；
- 不夸大创新性和效果；
- 不写无法验证的“首次”“独创”“显著优于”；
- 不把工具、文件路径和内部流程写入正文，除非竞赛明确要求报告软件环境。

### 3.5 图表与结果

图表必须服务于结论：

- 图前说明绘图目的，图后解释关键现象；
- 表前说明数据含义，表后回答题目问题；
- 正文关键数值与结果附件来自同一可复现输出；
- 临界问题应给出边界前后或约束余量；
- 结果解释不重复模型推导。

## 4. 单题默认结构

蓝图未另行规定时采用：

```text
X.1 本问目标与承接关系
X.2 本问新增模型
X.3 求解算法与参数设置
X.4 求解结果与分析
X.5 可靠性检验
X.6 本问结论
```

公共模型的首次所有者章节可展开为：

```text
X.1 问题分析
X.2 模型假设与符号
X.3 基础模型建立
X.4 算法求解
X.5 结果与验证
```

章节结构以蓝图为准，不能机械要求每问重复“模型假设”和“符号说明”。公共假设与公共符号应在首次位置统一给出。

## 5. 输出前检查

必须检查：

- 是否使用了未在成果包中出现的模型或结果；
- 是否重新定义前文公式；
- 是否出现标签冲突、跳号或同号异式；
- 是否把算法容差误写为题目约束；
- 是否遗漏题目指定的结果、时刻、对象、单位和精度；
- 是否存在内部流程、工具说明或建议式语言；
- 是否通过 `checks/check_formula_reuse.py`；
- 正文与 Excel、CSV、图表和登记库是否一致。

## 6. 成稿原则

论文不是建模探索过程的逐字记录，而是对已验证研究成果的组织与表达。正文必须保留支撑结论所需的数学链条，同时删除失败路线、重复定义、调试细节和不影响理解的程序保护条件。
