# 第一层：建模与求解

## 1. 职责

本层只解决“题目怎样被正确、可复现地算出来”。允许进行探索、比较、试错、补充约束和数值实验，但不得为了论文排版而删改数学逻辑，也不得直接生成可拼接进论文的最终正文。

本层负责：

- 题目与附件解析；
- 逐问任务、输入、输出和约束拆解；
- 数据清洗、单位统一和参数来源核验；
- 模型假设、变量、状态量和决策变量设计；
- 候选模型比较与路线选择；
- 公式推导、算法设计和代码实现；
- 数值求解、结果文件生成和精度检查；
- 灵敏度、稳健性、残差、边界与临界性验证；
- 形成供后续两层使用的结构化建模成果包。

本层不负责：

- 决定论文最终章节顺序；
- 分配最终公式编号；
- 为避免篇幅而省略关键计算约束；
- 将探索过程原样写入论文；
- 使用“本文”“本问”口吻生成最终论文正文。

## 2. 强制输入

执行前只读取与当前问题直接相关的上下文：

1. 项目配置文件；
2. 题面与当前问题附件；
3. 项目 `registry/parameters.yaml`；
4. 项目 `registry/formulas.yaml`；
5. 项目 `registry/model_contracts.yaml`；
6. 当前问题依赖的前序建模成果包。

不得默认通读全部历史对话、全部项目文件或全部已完成章节。需要引用前序模型时，优先读取登记库与结构化成果包，以减少上下文和 token 消耗。

## 3. 工作流程

### 3.1 任务拆解

逐问明确：

- 必须输出的数值、图表、文件和证明；
- 已知量、未知量、控制量、状态量和约束；
- 题面显式条件与隐含物理条件；
- 与前序问题的继承关系；
- 可接受误差与结果精度。

### 3.2 基线方案与创新探索

在确定最终模型前调用 `support/INNOVATION_EXPLORER.md`。先列出常规基线方法，再针对题目特有矛盾形成多个改进路线。不得把“更复杂”“使用冷门算法”直接视为创新。

最终路线必须记录：

- 基线方法；
- 基线在本题中的具体不足；
- 所作改造及其数学必要性；
- 计算代价与失败风险；
- 可验证的预期收益；
- 选择该路线而放弃其他路线的理由。

### 3.3 建模

按照对象自然生成顺序建立模型：

```text
对象与状态定义
→ 基本几何/物理/统计关系
→ 局部约束或局部判据
→ 全局目标或全局判据
→ 可计算形式
```

关键数学动作不得跳过，包括积分、求导、投影、代入、递推、取极值、离散化、线性化和可行域构造。

本层公式使用稳定的语义 ID，而不是最终论文编号，例如：

```text
F-P1-HEAD-POSITION
F-P1-HANDLE-RECURSION
F-P2-COLLISION-MARGIN
```

语义 ID 用于跨问题复用，最终式号由第二层统一分配。

### 3.4 算法与求解

模型与算法分开记录。算法说明至少包含：

- 输入与输出；
- 初值或粗估来源；
- 搜索区间或可行域；
- 迭代、扫描、优化或判定步骤；
- 停止准则与精度；
- 多解筛选和异常处理；
- 复杂度或主要计算瓶颈；
- 可复现代码、命令和随机种子。

### 3.5 结果与验证

任何结果必须能追溯到程序输出或明确计算。至少选择与问题匹配的验证方式：

- 方程残差与约束违反量；
- 临界点前后可行性变化；
- 多步长、多初值或多算法一致性；
- 参数敏感性与稳健性；
- 物理量级、单调性和边界合理性；
- 附件结果与正文关键数值一致性。

不得仅以“软件求得”“结果合理”作为验证。

## 4. 标准输出：建模成果包

每个问题完成后生成一个结构化成果包，推荐路径：

```text
<project>/artifacts/modeling/problemX.model.yaml
```

最低字段：

```yaml
problem_id: problemX
objective: "本问要解决的目标"
dependencies:
  models_reused: []
  formulas_reused: []
inputs: []
outputs_required: []
assumptions: []
symbols:
  reused: []
  new: []
model_components:
  - id: M-PX-01
    purpose: ""
    derivation: ""
    formulas: []
algorithms: []
results: []
validation: []
innovation:
  baseline: ""
  modification: ""
  evidence: ""
  limitations: ""
new_registry_entries:
  parameters: []
  formulas: []
  model_contracts: []
writing_notes:
  essential_claims: []
  omit_from_paper: []
status: solved|partial|blocked
```

`writing_notes` 只标记哪些结论必须在论文中体现、哪些探索过程不应进入论文，不得在本层直接写最终论文段落。

## 5. 完成门槛

只有同时满足以下条件，成果包才能交给第二层：

- 输出目标完整覆盖题目要求；
- 关键公式和算法可复现；
- 参数来源、单位和索引明确；
- 结果通过至少一种定量验证；
- 已更新待登记的公式、参数和模型边界；
- 已区分“计算所需约束”和“论文必须呈现内容”；
- 创新点有明确基线、改造和验证依据，未作无法证明的独创性声明。
