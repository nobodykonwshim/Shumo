# 公式库与模型边界审查协议

本协议是 `skills/math_modeling/SKILL.md` 的补充约束，用于避免数学建模论文在后续问题中重复定义已经建立过的公式、变量和模型。凡用户要求“使用数模 skill”“建模与求解”“论文版”“完整模型”“继续写下一问”时，均应同时遵守本协议。

## 1. 核心原则

数学建模论文应区分“已有模型”和“本问新增模型”。已经在前一问或前文中建立过的基础公式，后续问题只能引用、调用或说明其参数替换，不得再次完整推导或重复展开。

必须遵循以下规则：

1. 基础模型只在首次出现的问题中完整建立；
2. 后续问题若需要使用该模型，应写“沿用式……”“调用前文模型……”或“将前文模型中的参数替换为……”；
3. 每一问只新增解决本问目标所必需的变量、约束、目标函数、判定函数和求解算法；
4. 输出 LaTeX 前必须审查是否重复出现已有公式、已有坐标表达、已有递推关系或已有碰撞判定模型；
5. 若发现重复定义，应立即改写为引用式表述，不得继续输出重复模型。

## 2. 写作前强制检查流程

每次撰写新问题前，必须先完成以下检查：

```text
第一步：列出前文已经建立的基础公式和模型；
第二步：明确本问允许新增的模型对象；
第三步：列出本问禁止重复定义的公式、变量和推导；
第四步：正文中只写本问新增内容，已有模型用式号引用；
第五步：输出前检查是否出现禁止重复表达。
```

推荐在每一问开头加入边界说明，例如：

```latex
本问沿用前文已经建立的位置递推模型与碰撞判定模型，不再重复给出基础轨迹方程、坐标表达和实体几何构造公式，仅针对本问新增的优化变量和可行性判定函数进行建模。
```

## 3. 公式库管理方式

建议在仓库中维护公式库文件，例如：

```text
skills/math_modeling/registry/formulas.yaml
skills/math_modeling/registry/model_contracts.yaml
skills/math_modeling/registry/symbols.yaml
```

公式库至少记录以下内容：

```yaml
formula_id:
  label: "eq:xxx"
  name: "公式名称"
  meaning: "公式含义"
  first_defined_in: "首次出现的问题或章节"
  reuse_rule: "后续是否只允许引用"
  forbidden_redefine: true
```

## 4. 模型边界管理方式

每个问题都应有独立的模型边界：

```yaml
problemX:
  must_reference:
    - "必须沿用的已有公式或模型"
  forbidden_redefine:
    - "禁止重复推导的公式或模型"
  allowed_new_models:
    - "本问允许新增的模型"
  review_before_output:
    - "输出前必须检查的项目"
```

## 5. 板凳龙问题专用规则

在“板凳龙”项目中，应固定采用以下模型边界。

### 问题一

问题一是基础运动模型建立部分，允许完整建立：

- 等距螺线方程；
- 直角坐标表示；
- 弧长函数；
- 龙头前把手运动模型；
- 相邻把手位置递推模型；
- 速度递推模型。

### 问题二

问题二允许新增：

- 板凳矩形实体表示；
- 非相邻板凳碰撞判定；
- 终止时刻搜索模型。

问题二不得重新推导问题一中的螺线方程、直角坐标表达、弧长函数和速度递推来源，只能引用。

### 问题三

问题三只允许新增：

- 候选螺距变量 `p`；
- 龙头半径搜索区间；
- 候选螺距安全裕度；
- 最小螺距可行性判定；
- 外层螺距二分与内层安全裕度搜索。

问题三禁止重复定义：

- 等距螺线极坐标方程；
- 等距螺线直角坐标表达；
- 螺线弧长函数；
- 龙头前把手位置模型；
- 相邻把手位置递推模型；
- 板凳矩形实体模型；
- 非相邻板凳碰撞判定模型。

正确写法是：

```latex
本问不再重复建立螺线位置模型，而是将问题一中已有模型的螺距参数替换为候选值 p，并沿用问题二中的安全裕度判定模型判断可行性。
```

### 问题四

问题四只允许新增：

- 盘入、盘出螺线之间的中心对称关系；
- S 形调头曲线；
- 两段圆弧相切条件；
- 半径比约束；
- 调头曲线唯一性证明；
- 统一路径弧长参数化。

问题四禁止重复完整推导问题一的位置递推和速度递推，只能说明“沿统一路径调用同一刚性孔距递推思想”。

### 问题五

问题五只允许新增：

- 单位龙头速度下的速度放大系数；
- 全路径最大速度放大系数；
- 龙头最大速度计算公式；
- 临界时刻和最坏把手识别。

问题五禁止重新建立路径几何、调头圆弧、位置递推和完整速度递推来源，只能引用问题四模型。

## 6. 输出前审查清单

在输出任意一问 LaTeX 之前，必须逐项检查：

```text
是否重复写了前文已经定义的轨迹方程？
是否重复写了前文已经定义的坐标表达？
是否重复写了前文已经定义的弧长函数？
是否重复写了前文已经定义的板凳实体模型？
是否重复写了前文已经定义的碰撞判定模型？
本问是否只新增了当前问题真正需要的新变量、新约束和新目标？
公式标签是否与前文冲突？
正文是否使用“沿用式”“调用前文模型”“参数替换”等引用式表述？
```

只要其中任一项不满足，应先修改，不得直接交付。

## 7. 推荐仓库工作流

```text
1. 在 registry/formulas.yaml 中登记已定义公式；
2. 在 registry/model_contracts.yaml 中登记每一问的模型边界；
3. 写新章节前读取 model_contracts.yaml；
4. 写完后运行 checks/check_formula_reuse.py；
5. 若发现重复定义，改为引用前文公式；
6. 通过审查后再输出 LaTeX、Word 或论文正文。
```

## 8. 优先级

本协议的优先级高于“章节自洽性”。后续问题为了自洽可以简述前文模型用途，但不得重复展开前文公式。若“完整性”和“避免重复”冲突，应优先避免重复，并通过式号引用保证完整性。
