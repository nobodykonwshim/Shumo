# Innovation Explorer：创新探索协议

## 1. 目的与准入

本模块用于帮助参赛者在常规解法基础上形成与题目特征紧密相关、可验证、可解释的改进方案。它是第一层中的可选 `route_explorer` Agent，不构成第四层，也不直接生成论文中的“创新点”段落。

本模块不得默认对每一道题运行。调用前必须完成 `AGENT_ADMISSION_GATE.md`：只有路线空间确实开放、创新探索具有足够价值、关键能力可靠且错误可通过基线与验证发现时，才允许启用。

若候选路线和选择规则已经可以枚举，应直接使用 Workflow，不建立 Agent 循环。

AI 无法保证某一方案在所有参赛队伍中绝对唯一。因此，本模块追求的不是凭空生成“别人想不到的方法”，而是通过明确的比较、改造和验证过程，使最终方案具有参赛者自己的判断链和题目针对性。

## 2. 运行边界

每次运行必须明确：

- 可读取的题面、项目登记库和直接依赖成果；
- 最大候选数量、迭代次数和工具调用次数；
- 允许提出候选，不允许修改登记库和最终论文；
- 以基线差异、数学理由和验证计划作为证据；
- 达到预算、候选开始重复或证据不再增加时停止；
- 最终路线必须经过参赛者或团队确认。

## 3. 禁止的伪创新

以下内容不能单独作为创新：

- 仅把常规模型换成更复杂或更冷门的算法；
- 仅堆叠多个模型而没有必要性；
- 仅提高采样精度、迭代次数或代码复杂度；
- 仅使用“智能”“自适应”“多目标”等名称；
- 没有对照实验或数学理由的参数调整；
- 无法说明与基线差异的“综合模型”；
- 未检索或未比较就宣称“首次”“独创”。

## 4. 创新来源

优先从以下位置寻找改进：

1. **题目特有结构**：几何对称、守恒关系、单调性、稀疏性、周期性、分段性、尺度差异；
2. **常规模型失效点**：多解、局部最优、边界不稳定、计算量过大、噪声敏感、参数不可辨识；
3. **问题间继承关系**：把前一问模型转化为后一问的状态、约束、代理模型或可行域；
4. **算法结构改造**：粗筛—精判、解析降维—数值精修、事件驱动、活跃集、分层搜索、自适应网格；
5. **验证体系**：临界性证明、残差闭环、多尺度稳定性、反事实对照、误差传播或不确定性量化；
6. **表达与求解统一**：用稳定公式 ID、模型合同和成果包减少跨问题重复。

## 5. 标准流程

### 5.1 建立基线图谱

列出 2—4 条合理的常规路线，每条记录：

- 核心模型；
- 适用条件；
- 优点；
- 本题中的具体缺陷；
- 计算代价；
- 预期结果质量。

候选数量不得超过准入记录中的预算。

### 5.2 提取题目摩擦点

“摩擦点”是常规方法在本题中遇到的具体困难，例如：

- 全时域扫描成本过高；
- 碰撞判定存在大量无关对象对；
- 目标函数不可导但具有单调边界；
- 多个问题重复使用同一运动学模型；
- 参数变化导致公式重新推导；
- 结果只给数值，无法证明临界性。

### 5.3 构造候选路线

候选可覆盖：

- **稳妥改进型**：在成熟模型上做题目针对性改造；
- **结构利用型**：利用对称性、单调性、线性缩放或稀疏性降低维数或计算量；
- **验证增强型**：模型变化不大，但建立更强的可靠性、临界性或不确定性验证。

每条候选使用：

```yaml
candidate_id: I-PX-01
baseline: ""
problem_specific_gap: ""
modification: ""
mathematical_rationale: ""
expected_gain: ""
validation_plan: ""
implementation_cost: low|medium|high
risk: low|medium|high
```

### 5.4 形成决策矩阵

按以下维度评分：

- 正确性风险；
- 题目适配度；
- 可解释性；
- 可复现性；
- 计算成本；
- 可验证性；
- 论文表达价值；
- 与基线的实际差异。

优先选择题目适配度高、可验证、风险可控的路线，而不是最复杂的路线。

### 5.5 参赛者决策留痕

最终方案应记录：

- 为什么接受某一改进；
- 为什么放弃其他候选；
- 哪个假设或风险需要额外验证；
- 哪些部分体现了参赛者自己的判断。

Agent 只提供候选与证据，不得静默做出最终路线选择。

## 6. 停止条件

出现以下情况立即停止：

- 达到候选、迭代或工具预算；
- 新候选与已有候选实质重复；
- 连续两轮没有新增可验证证据；
- 关键缺口依赖题面之外的未知信息；
- 需要参赛者在风险、时间和创新价值之间作取舍；
- 无法设计验证方案。

停止时返回当前候选、证据、未解决问题和需要的人工决策。

## 7. 论文中的创新表达条件

只有满足以下条件，第三层才可将其写为创新点：

- 已明确对比基线；
- 改造与题目困难存在直接因果关系；
- 改造进入实际模型或算法；
- 有计算、证明或对照验证支撑；
- 能说明收益和适用边界；
- 不使用无法核实的绝对独创性表述。

推荐表述形式：

```text
针对……导致的……问题，本文在常规……方法基础上引入……机制，
从而将……转化为……。对比、误差或稳定性结果表明，该改造在……方面具有优势。
```

## 8. 与三层架构的关系

- 第一层在准入通过后调用本模块产生有限候选；
- 参赛者确认路线后，Workflow 完成规格化、实现和验证；
- 第二层决定已验证创新的放置位置；
- 第三层仅按蓝图写成正式论文，不再临时包装创新点。
