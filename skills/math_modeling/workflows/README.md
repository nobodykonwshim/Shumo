# Shumo Workflow Map

## 1. 总体原则

Shumo 采用 `Workflow first, Agent when justified` 的编排方式。

确定性、可枚举、可验证的任务使用 Workflow；只有开放探索、非预期调试和高价值方案评审，在通过 Agent 准入闸门后才允许使用受控 Agent。

## 2. 标准主流程

```text
W0 项目初始化
→ W1 题目解析与交付清单
→ G1 Agent 准入判断
→ A1 候选路线探索（可选）
→ H1 参赛者路线确认
→ W2 模型规格化
→ W3 代码实现与数值求解
→ W4 结果验证
→ G2 评审 Agent 准入判断
→ A2 方案压力测试（可选）
→ W5 登记库与成果包固化
→ W6 论文架构与编号蓝图
→ W7 论文写作
→ W8 一致性与交付检查
→ H2 逐问论文审核（可配置）
→ 下一问题 W0
```

其中 `W` 为确定性 Workflow，`G` 为准入闸门，`A` 为可选受控 Agent，`H` 为人工决策点。

## 3. 各 Workflow 定义

### W0 项目初始化

输入：题面、附件、竞赛规则。

固定步骤：

1. 创建或读取 `project.yaml`；
2. 确认目录、单位、语言、输出格式和页数；
3. 检查登记库是否存在；
4. 建立回滚点和当前问题 ID；
5. 输出项目状态清单。

### W1 题目解析与交付清单

固定输出：

- 每问输入、输出、约束；
- 指定文件、字段、单位和精度；
- 与前问依赖关系；
- 显式未知信息；
- 可验收标准。

本步骤禁止提出完整建模方案，以免把题意解析和方案探索混合。

### G1 Agent 准入判断

调用 `support/AGENT_ADMISSION_GATE.md`。

- 若问题路线可直接枚举且已有成熟选择，跳过 A1；
- 若存在多个合理路线、关键结构未知或需要创新探索，允许 A1；
- 若关键能力或错误检测不足，进入人工检查或阻塞状态。

### A1 候选路线探索（可选）

可调用 `INNOVATION_EXPLORER.md`，但必须限制候选数量、工具调用和停止条件。

输出候选，不直接决定最终路线。

### H1 参赛者路线确认

记录：

- 选择的路线；
- 放弃其他路线的原因；
- 可接受风险；
- 需要追加的验证。

没有该记录，不进入 W2。

### W2 模型规格化

把已选路线写成可执行规格：

- 对象、变量、参数和单位；
- 假设；
- 公式语义 ID；
- 约束和可行域；
- 输入输出；
- 算法步骤；
- 边界和异常情况；
- 测试计划。

本步骤不允许继续无限扩展候选路线。

### W3 代码实现与数值求解

按规格执行：

1. 建立最小可运行样例；
2. 实现核心模型；
3. 添加断言、日志和测试；
4. 运行并生成结果；
5. 对失败进行分类。

常规失败按预定义修复分支处理。只有无法枚举原因的调试问题，重新经过准入闸门后才能调用 Agent。

### W4 结果验证

至少执行：

- 单位与维度检查；
- 方程残差或约束违反量；
- 边界、极值或手算小样例；
- 步长、初值或参数扰动；
- 结果文件 schema 和完整性检查。

验证规则必须在看到最终结果前尽量预先定义，避免事后挑选有利指标。

### G2 评审 Agent 准入判断

当任务价值高、存在隐藏错误风险且已有可执行测试时，可调用 `SOLUTION_REVIEW_AGENT.md`。

若错误难以发现且没有反例、残差或对照机制，不能用 Agent 自主批准方案，必须人工评审。

### A2 方案压力测试（可选）

输出风险、反例、简化机会和追加验证，不直接改登记库或论文。

### W5 登记库与成果包固化

固定步骤：

1. 生成或更新 `problemX.model.yaml`；
2. 提交参数、公式和模型合同候选变更；
3. 检查语义 ID 冲突；
4. 标记验证证据和未解决限制；
5. 将状态设为 `solved`、`partial` 或 `blocked`。

### W6 论文架构与编号蓝图

由第二层执行：

- 指定模型和公式唯一所有者；
- 分配最终标签和章节位置；
- 决定继承、引用和新增内容；
- 分类正文、算法、附录和省略项；
- 控制篇幅。

### W7 论文写作

由第三层严格依据蓝图执行。禁止重新探索、重新求解、重新编号和临时包装创新。

### W8 一致性与交付检查

固定检查：

- 公式无重复定义；
- 编号无冲突；
- 正文数值与结果文件一致；
- 图表、字段、单位、精度齐全；
- 题目要求全部覆盖；
- 未验证声明没有进入正文。

### H2 逐问论文审核（可配置）

当项目配置 `question_delivery.mode: sequential_review` 时，W8 后必须执行
`../support/PROBLEM_REVIEW_GATE.md`。把当前问题的模型规格、论文蓝图、LaTeX 和结果文件哈希写入
审核记录并设为 `pending`。只有用户将该 revision 明确批准，且验证器确认前序顺序和哈希均一致时，
才允许进入下一问题。修改任何绑定产物后必须增加 revision 并重新审核。

## 4. Agent 插槽

Shumo 默认只保留三类 Agent 插槽：

1. `route_explorer`：候选模型和创新路线探索；
2. `diagnostic_agent`：非预期代码或数值问题诊断；
3. `solution_reviewer`：方案压力测试。

其他任务默认使用 Workflow。新增 Agent 类型前，必须证明现有 Workflow、工具和 Prompt 无法稳定解决该问题。

## 5. 失败路由

```text
题意缺失 → W1 补输入
路线不可行 → H1 / A1 重新选择
规格不完整 → W2
代码失败且原因已知 → W3 固定修复分支
代码失败且原因未知 → G1 → diagnostic_agent
验证失败 → W2 或 W3
评审发现重大问题 → W2 / H1
蓝图冲突 → W5 或第一层
写作缺数据 → W5，不得在 W7 猜测
```

## 6. 最小化复杂性

优化顺序固定为：

```text
改进 Prompt
→ 改进工具输入输出
→ 增加确定性检查
→ 增加单次候选生成
→ 最后才增加多轮 Agent
```

行为未稳定前，不引入多 Agent 讨论、长期记忆、自主递归规划或无限反思循环。
