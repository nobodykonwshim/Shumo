### 关键观察

#### 观察 1：Workflow 正确阻止了“看参考论文直接开算”

原题面和附件尚未读取，因此当前状态保持 `partial`，问题四保持 `blocked`。这是预期行为：参考论文只能帮助形成对照，不能替代原始输入。

#### 观察 2：问题一、二不需要 Agent

这两问的输入、几何关系、输出表和验证方式均可枚举，使用确定性 Workflow 更合适。把它们包装成 Agent 只会增加上下文和错误路径。

#### 观察 3：问题三适合人工检查点，而非默认 Agent

三篇参考论文均报告 34 条测线、总长度 68 海里（125936 m），说明主流路线高度收敛。系统可以有限提出边界布线或证明方案，但最终路线仍应由参赛者确认。

#### 观察 4：问题四才是 Agent 的合理候选

三篇论文对问题四给出的结果差异明显：

- 总测线长度约 434662 m、466394.4 m 和 1151944 m；
- 漏测率约 0.04%、2.3% 和 3.48%；
- 已报告的重叠率超过 20% 部分长度为 21998 m 和 55560 m。

分歧表明 terrain representation、区域划分、目标优先级和重叠率计算会强烈影响结果。这里可以使用受控 Route Explorer，但前提是先读取附件并建立独立空间验证器。

#### 观察 5：环境能力检查必须前置

当前运行环境能读取 RAR 目录，却不能解压。若没有 W0 环境预检，系统可能在中途才发现无法读取关键附件。因此后续应把 archive extraction capability 加入项目初始化的固定检查。
